# remote-dev 0.11.12: Remote NPU Job Storage Caps & Terminal GC, Local State Retention, and Test Temp-Dir Leak Fix

[中文](remote-dev-0.11.12.md)

- **Bounded Remote Job Logs with Honest Truncation Accounting (`processes/worker.py`, `processes/worker_runtime.py`)**: PTY and pipe output now flows through `CappedLog`, which keeps `<stream>.log.prev` + `<stream>.log` at or below `spec.max_log_bytes` (default `256 MiB` per stream) instead of appending without bound. `logs.json` and `result.json` record `logical_bytes_written` / `truncated_head_bytes`; `tail`/`exchange` keep logical-offset semantics and return `*_truncated`, `*_skipped_bytes`, `*_logical_bytes`, and `*_truncated_head_bytes` when the head has rotated away, so callers never mistake ring loss for clean EOF.
- **Safe-Ownership Terminal Remote Job GC (`processes/worker_runtime.py`, `core/job_ops.py`)**: `.remote-dev/jobs` is pruned at `7 days` TTL, `128` terminal jobs, and `2 GiB`. Only directories owned by the current remote `os.getuid()`, with no held `worker.lock`/`lock`, a definitively terminal `result.json` state, an empty `unknown` field, and `descendants_drained is True` or a freshly observed `quiet` status are considered; `running`, `starting`, `stopping`, `unknown`, and `retain_until_release` jobs are never removed. Removal atomically renames to `.trash-<job_id>-<token>` and then deletes. GC is capped at `512` observations, cooled down for `300s`, and triggered opportunistically from job start and stop paths.
- **Local Endpoint State Retention & Dead-Session Cleanup (`core/retention.py`, `core/state_store.py`, `core/job_ops.py`)**: Per-endpoint `reads/` and `logs/` expire after `7 days` / `256` entries / `128 MiB`; local `jobs/<job_id>.*` artifacts are pruned only when the persisted record is definitively terminal, after `14 days` / `128` records / `256 MiB`. `running` and `unknown` records are preserved. Write-triggered pruning uses a `300s` cooldown and a bounded `2s` budget, and a prune failure never blocks the already-committed write. The new `prune_stale_session_runtime_dirs()` removes only `gate-v1*`/`runtime*`/`session*` directories with a provably dead PID, no held lock, and age over `24h`; any directory containing a SQLite receipt store is strictly preserved (`remote-dev` does not own the `gate-v1` layout, so this is an explicit helper for its consumer).
- **Test Temp-Dir Leak Fix (`tests/test_native_contracts.py`)**: `test_tail_text_reads_bounded_suffix_without_whole_file` now uses `tempfile.TemporaryDirectory`, and a new regression asserts no `tail-bounded-*` directory is added to `$TMPDIR`, eliminating the per-run `64 MiB` sparse-file residue.
- **Version & Packaging**: `0.11.11` → `0.11.12`; `worker_runtime.py` is included in the wheel `force-include` and the composed remote worker source; `tests/test_retention.py` covers remote terminal GC, ring-log accounting, local `reads`/`logs`/`jobs` retention, and receipt-store protection.

Verification: `pytest -q -m "not live_npu"` passes (`1040 passed, 60 skipped, 6 deselected`), the isolated `$TMPDIR` contains no `tail-bounded-*` leftovers, and every changed file uses Unix `LF`.
